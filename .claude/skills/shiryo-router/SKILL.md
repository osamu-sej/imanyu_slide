# 資料作成ルーター

資料作成スキルが10個あり、依頼の言い方によってどれが動くかが揺れる。
このスキルは**入口を1つにして、聞くべきことだけ聞いて、正しいスキルへ渡す**ためのもの。

自分で資料を作らない。**振り分けたら、そのスキルを呼んで仕事を明け渡す。**

---

## 1. まず「聞かずに直行できるか」を判定する

ユーザーが形式・ブランド・対象ファイルを既に言っているなら、質問は不要。
**聞くこと自体がコストなので、判定できるなら黙って直行する。**

| 依頼にこれが含まれる | 直行先 |
|---|---|
| 「セブンのテンプレ」「SEJの資料」「コーポレートテンプレ」「社内提出用のパワポ」 | `seven-eleven-pptx` |
| 「HTMLスライド」「16:9のHTML」「ブラウザで開くやつ」「shiryo-slides」 | `shiryo-slides` |
| 既存の `.pptx` / `.potx` を指している（読む・直す・抽出する） | `pptx` |
| 既存の `.docx` / `.dotx` を指している | `docx` |
| 既存の `.xlsx` / `.csv` を指している | `xlsx` |
| 既存の `.pdf` を指している（結合・分割・抽出・OCR） | `pdf` |
| 「週次報告」「社内ニュースレター」「通達」「FAQ」「プロジェクト更新」 | `sej-internal-comms` |
| 「構成だけ」「アウトラインだけ」「ストーリーを設計して」「台本を作って」 | `ppt-structure-design` |

上のどれにも当てはまらず、**何で出すかが決まっていない**ときだけ §2 に進む。

---

## 2. 選択式で聞く（AskUserQuestion・最大2回）

自由記述で聞かない。ユーザーは選ぶだけで済むようにする。

### Q1（必ず聞く）— 何を作るか

4択で出す。

| 選択肢 | 行き先 |
|---|---|
| スライド・プレゼン | Q2 へ |
| 文書（Word・PDF） | `docx`（最終形がPDFなら生成後に `pdf`） |
| 表・データ（Excel） | `xlsx` |
| 社内向けのテキスト（週次報告・通達・FAQ・ニュースレター） | `sej-internal-comms` |

スライド以外を選ばれたら、**ここで質問は終わり**。該当スキルへ渡す。

### Q2（スライドのときだけ）— 2問を1回にまとめて聞く

**問A: どの形で出しますか？**

| 選択肢 | 行き先 |
|---|---|
| .pptx ／ セブン-イレブンの公式テンプレ | `seven-eleven-pptx` |
| .pptx ／ 汎用モダン（社外提案・研修・個人プロジェクト） | 問Bと組み合わせて `ppt-build-standard` か `pptx-pro` |
| HTML 1枚（ブラウザで開く・そのままPDF化も可） | `shiryo-slides` |
| 既存の .pptx を直す・中身を取り出す | `pptx` |

**問B: 構成はどうしますか？**

| 選択肢 | 行き先 |
|---|---|
| 構成から一緒に設計したい | まず `ppt-structure-design` → 設計確定後に問Aの生成スキルへ |
| 材料はある（議事録・メモ・箇条書き） | 問Aの生成スキルへ直行 |
| 構成は確定している | 問Aの生成スキルへ直行 |

**「.pptx ／ 汎用モダン」を選ばれたときの分岐**

- `ppt-structure-design` の設計図がある、またはこれから作る → `ppt-build-standard`（設計図を入力に取る前提の作り）
- 設計図なしでゼロから凝ったデザインにしたい → `pptx-pro`

## 3. 判断に迷ったときの材料

質問に答えてもらう前に、ユーザーが迷いそうな軸はここ。**選択肢の説明文にこの中身を入れておく**と、選ぶだけで判断できる。

### .pptx か HTML か — ここが最大の分かれ目

| .pptx が要る | HTML（`shiryo-slides`）で足りる |
|---|---|
| 受け取った人が中身を編集する | 見るだけ・投影するだけ |
| 提出形式として .pptx を指定されている | 指定がない／自分で決められる |
| 既存のパワポに差し込む | 単体で完結してよい |
| 社内の正式フォーマットに乗せる | PDFで配れば足りる |

**提出形式の指定があるかを先に確認する。** ここを外すと作り直しになり、いちばん高くつく。

`shiryo-slides` は生成後に自分でスクリーンショットを撮って直す工程を持っているので、見た目の破綻（はみ出し・整列崩れ）が残りにくい。指定がないなら第一候補にしてよい。

### seven-eleven-pptx か ppt-build-standard か

**宛先で決まる。** 社内向け・SEJの名前で出すものは `seven-eleven-pptx`（ブランドガイドライン準拠の配色が入っている）。
社外提案・研修・個人プロジェクトなど、SEJのブランドを載せない場面は `ppt-build-standard`。

### 構成設計を挟むべきとき

材料が「テーマ1行」しかない、または話の順番が決まっていないなら、先に `ppt-structure-design` を通したほうが速い。
議事録やメモがある場合は、生成スキル側が構成設計を持っていることが多いので二度手間になる。**材料の量で決める。**

---

## 4. 渡し方

行き先が決まったら、次の3つをやる。

1. **どこへ渡すかを1行で伝える**（「HTMLスライドなので shiryo-slides に渡します」）。ユーザーが違うと思ったら止められる
2. **Skill ツールでそのスキルを呼ぶ**。ルーターの仕事はここで終わり
3. **材料をそのまま引き継ぐ**。ユーザーが貼った議事録・メモ・ファイルパス・宛先・期限は、要約せずに渡す

渡した先のスキルが独自に確認事項を持っている場合（`shiryo-slides` はスタイル・用途・テーマを聞く）、**それを先回りして代わりに聞かない**。スキルごとに選択肢が違うので、二重に聞くとユーザーが混乱する。

### 2段運用になる場合

`ppt-structure-design` → 生成スキル、の順で渡すときは、設計が確定した時点で
「この設計図で `ppt-build-standard` に渡します」と一言置いてから次を呼ぶ。
設計だけ見て終わりたい人もいるので、勝手に生成まで走らない。

---

## 5. このスキルを使わない場面

- 資料の**中身の相談**（何を書くべきか、切り口はどうするか）→ `fukabori` で壁打ちする
- BigQuery のテーブル・カラムを調べたい → `sej-table-schema`
- 既にどのスキルで作るか決まっている → そのスキルへ直行（§1）
- グラフ・チャートが主役 → 生成スキルに渡したうえで、図の作り方は `dataviz` を併用する
